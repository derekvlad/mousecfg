## Как использовались материалы по вендорскому протоколу YJX

Для мышей на контроллере YJX (AJAZZ 2.4G) читались два независимых описания,
оба — только как **справочник по протоколу**: оттуда взяты факты о кадрах,
а не код.

* `deepinthewoods/mkespn` (`PROTOCOL.md`, MIT) — формат 64-байтного кадра
  vendor-канала (`55 …` запрос, `aa …` ответ) и назначение команд
  (`03/00` идентификация, `08/a5` страницы режимов, `0e/a5` DPI/частота/
  подсветка, `0d/00` запись раскладки, стирающая память при непустом теле).
* npm `yjx-sdk-mouse` (лицензия не заявлена) — второй диалект кадра
  (`f0 …` с адресами памяти), назначение команд (`08` короткое чтение,
  `0e` повтор, `30` заряд, `52` рукопожатие) и база области чтения
  `0x0ba5`.

Код этих проектов не копировался: `src/mousecfg/vendor/` написан заново,
проверки «только чтение» в `vendor/guard.py` — собственная политика проекта.
Пакету `yjx-sdk-mouse` лицензия не сопутствует, поэтому он используется
исключительно как источник фактов о протоколе.

## Как использовался установленный Solaar

На машине разработки установлен `solaar 1.1.20`
(`/usr/lib/python3.14/site-packages/logitech_receiver/`). Он читался как
**справочник по протоколу**: оттуда взяты факты, а не выражения.

Факты (не охраняются авторским правом):

* идентификаторы фич HID++ 2.0 (`0x2201` DPI, `0x8060` report rate,
  `0x8100` onboard, `0x8071` подсветка, `0x8110` button spy и т. д.);
* номера функций внутри фич (`0x10` чтение, `0x20` запись, `0x50` чтение
  сектора) и значения режимов (`0x01` On-Board, `0x02` Host);
* коды кнопок Logitech (`0x0050` левая, `0x0051` правая, `0x0052` средняя,
  `0x0053` Back, `0x0056` Forward, `0x00C4` DPI);
* поведение транспорта: `0x10`/`0x11`, индекс устройства `0xFF` для
  проводного подключения, Software ID как младший ниббл байта функции.
