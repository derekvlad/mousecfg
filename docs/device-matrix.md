# Матрица устройств

**Русский** · [English](en/device-matrix.md)

Здесь фиксируется только то, что реально проверено на железе. Каждая строка —
результат прогона `mousecfg` и, где это возможно, анализ трафика.

## Logitech G102 LIGHTSYNC (046d:c092)

Проверено 2026-11-11, прошивка `U1 52.00.B0010`, HID++ 4.2, серийник `205C35585247`.
Повторная проверка макросов после перезагрузки — 2026-11-12, systemd 262.

| Что | Значение |
|---|---|
| HID++ узел | `/dev/hidraw2` (interface 1), второй узел `/dev/hidraw1` — обычная мышь |
| Режим до правки | `On-Board` (настройки с хоста игнорировались) |
| Режим после `mousecfg mode host` | `Host`, сохраняется между переоткрытиями устройства |
| DPI | чтение/запись работают, `ADJUSTABLE_DPI 0x2201` |
| Report rate | поддерживаются 1/2/4/8 мс, чтение/запись работают |
| Onboard-профили | есть, **1 слот**; `ONBOARD_PROFILES 0x8100` |
| Divert кнопок | **нет** (`REPROG_CONTROLS_V4 0x1B04` отсутствует) → ремап только через evdev/uinput |
| LED | `RGB_EFFECTS 0x8071`: 1 зона (logo), effects Ids `0x00 disabled, 0x01 static, 0x03 cycle, 0x04 wave, 0x0a breathe, 0x0d, 0x0e decomposition`; `PER_KEY_LIGHTING_V2 0x8081` (3 светодиода) |
| Скрытые фичи | `0x1801, 0x18a1, 0x18b1, 0x1e22, 0x1eb0` — не используются |

### Подсветка (`RGB_EFFECTS 0x8071`)

Протокол проверен на живом устройстве:

* `getInfo` (fn `0x00`, params `FF FF 00`) → 1 зона, capabilities `0x0004`;
  бит `0x0001` (readable) снят, то есть текущий эффект прочитать нельзя.
* Информация о зоне — та же функция `0x00` с `(zone, FF, 00)`; смещение
  `[2:5]` = `location` u16 BE + число эффектов; у G102 `location = 2` (logo),
  7 эффектов.
* Описание эффекта — fn `0x00` с `(zone, slot, 00)`.
* **Волатильная запись эффекта — fn `0x10`**: `zone + slot + 10 байт
  параметров + 0x01`. Именно её использует проект; она не пишет в
  энергонезависимую память.
* **Перед каждой записью эффекта нужен `setSwControl` — fn `0x50`** с
  `01 03 04` (subfn=set, mode=3 «полный SW-контроль», flags=`0x04`).
  Без него прошивка продолжает рисовать цвет onboard-профиля и `setZoneEffect`
  визуально ничего не делает. Команда волатильная (RAM до отключения мыши).
  Является ответом на «подсветка не работает»; тот же приём у Solaar
  (`rgb_power.SW_ACTIVE`). Персистентная `ONBOARD_PROFILES 0x10 [02]` для
  открытия управления не требуется — проверено.
* **Персистентная запись NvConfig — fn `0x30`** (другая функция), запрещена
  политикой (`guard`).
* Проверено: `static red/green/blue` переключаются верно подряд через штатный
  путь (демон + CLI); `breathe` включается и держится до переподключения;
  недоступный эффект и неизвестный параметр отклоняются с ошибкой.

### Что даёт «не писать во флеш»

* Все настройки, которые применяет проект, — волатильные команды HID++ 2.0;
  после отключения мыши они сбрасываются, и это ожидаемое поведение.
* Единственная персистентная операция — однократный переход
  `On-Board → Host` (`0x8100/0x10`). Он выполняется только с
  `--allow-onboard-switch` и попадает в журнал как `persistent-consented`.
* Запрещены и никогда не уходят: `0x8100/0x30`, `0x8100/0x60..0x80`
  (запись onboard-профилей), `0x1802` (reset), `0x1806/0x20`, `0x1e00`,
  `0x00c2/0x20` (прошивка), `0x8071/0x30` (NvConfig подсветки).
  Проверяется тестами в `tests/test_guard.py`.

### Что проверено на живом устройстве

| Проверка | Как | Результат |
|---|---|---|
| Отказ политики | `device.request(0x8100, 0x60)`, `0x1802/0x00`, `0x1e00/0x00` | `DeniedCommand`, в устройство ничего не уходит |
| Ноль персистентных кадров | `python3 scripts/capture-hid.py -- python3 -m mousecfg set-dpi 2400` | «Персистентных операций: 0» |
| DPI волатильно | `set-dpi` → перечитать → `set-dpi` | значение меняется в пределах сессии (800↔1600↔3200) |
| Rate волатильно | `set-rate` 1/2/4/8 мс | значение принимается и читается обратно |
| Демон | `mousecfg daemon -v` + `mousecfg status` | находит мышь, применяет `default`, видит активное приложение |
| Профиль по приложению | профиль `browser` с `match_apps = ["Vivaldi-flatpak"]` | при активном Vivaldi DPI стал 3200, затем вернулся к 1600 |
| GUI | `mousecfg-gui` при запущенном демоне | окно строится, кнопка «Применить» переключает профиль (800↔1600) |
| Права на evdev-узел | `data/70-mousecfg-input.rules` + `udevadm trigger` | `/dev/input/event3` доступен: `getfacl` даёт `user:derek:rw-`, `mousecfg inputs` показывает мышь и её кнопки |
| ACL переживает `change` | `udevadm test --action={add,change}` на event3 с правилами из `data/` | с `ACTION!="remove"` builtin `uaccess` попадает в очередь и на `add`, и на `change` (с `ACTION=="add"` — только на `add`; после перезагрузки ACL не появлялся) |
| Ремап кнопок | `mousecfg run-profile examples/g102-buttons.toml --seconds …` | `EVIOCGRAB` встаёт, события ретранслируются, `--seconds` корректно выключает перехват |
| Подсветка волатильно | `mousecfg lighting --effect static --color '#ff0000' --brightness 50`, затем `breathe` | эффект включается, `static` притемняет цвет (0x800000), `breathe` шлёт `intensity`; держится до переподключения; `fn 0x30` отклоняется как `DeniedCommand` |
| Подсветка берёт SW-контроль | `mousecfg lighting --effect static --color '#00ff00'` на мыши в host | перед `setZoneEffect` уходит `setSwControl 01 03 04`; красный/зелёный/синий переключаются верно подряд (без claim цвет «залипал» на onboard-профиле) |
| Трей и хоткей | `mousecfg-tray` + панель StatusNotifierWatcher | иконка `mousecfg` регистрируется; на niri трей портал не трогает и не плодит зависших окон |
| Автозапуск трея | `sh scripts/install-user.sh` + `systemctl --user daemon-reload` | юнит `app-io.github.mousecfg.MouseCfg-tray@autostart.service` генерируется из `~/.config/autostart` (в `Exec=` абсолютный путь) и привязан к `xdg-desktop-autostart.target`; иконка появляется в панели `noctalia` |
| Автопереход в Host | `mousecfg mode host --allow-onboard-switch`, ребут, `systemctl --user restart mousecfg-daemon` | согласие в `~/.local/state/mousecfg/host-consent.json`; при повторном подключении мыши в On-Board демон сам уходит в `host` (в журнале «автоматический переход»), `mousecfg status` показывает `режим: host` |
| Хоткей через niri | `mousecfg keybinds --install` + `niri msg action load-config-file`, затем `Alt+Shift+Right` | активный профиль переключается на следующий (`default`→`shooter`) |
| Профиль не сбрасывается | `mousecfg profile activate game`, затем сменить активное окно | профиль остаётся `game` (раньше возвращался на первый, `default`); профиль с `match_apps` всё равно важнее |
| Макросы после перезагрузки | после ребута переустановлено правило 70 → `udevadm trigger --subsystem-match=input`, демон перезапущен, нажаты боковые кнопки | `side2` → `ctrl+shift+F12`, `side1` → `ctrl+shift+F11`: на виртуальном узле видны нажатия `LEFTCTRL`+`LEFTSHIFT`+`F12`/`F11`. Демон пишет `remap_active: true`, ошибок в журнале нет |
| Запись макроса в GUI | в диалоге профиля выбрать кнопку `side1`, «Записать макрос», нажать `Ctrl+Shift+T` | шаг `ctrl+shift+T` появляется списком, макрос сохраняется с id `профиль-side1` и подставляется в назначения кнопки |
| Запись не зависит от раскладки | при русской раскладке записать `abc`, `Shift+1`, `-`, `F4` | в шагах ровно `A B C`, `shift+1`, `KEY_MINUS`, `F4` (раньше по символам почти всё терялось) |
| Сквозная проверка evdev | виртуальный источник → `Remapper` → виртуальный приёмник | движение насквозь; `side1`→`ALT+LEFT`, `middle`→`CTRL+C`, `side2`→макрос; непривязанная `BTN_RIGHT` проходит как есть; p95 ≈ 0.4 мс |
| Виртуальное устройство | `data/71-mousecfg-virtual.rules` | `/dev/input/eventN` устройства `mousecfg virtual input` получает ACL пользователя сессии |

### Что нужно проверить вручную

| Проверка | Как | Ожидание |
|---|---|---|
| Волатильность через переподключение | `python3 scripts/replug-test.py` (задать значения, затем физически переподключить мышь) | после переподключения значения возвращаются к дефолту |
| Независимый дамп USB | `sudo python3 scripts/capture-hid.py --usbmon capture.pcap -- python3 -m mousecfg set-dpi 1600` | в трафике нет `0x8100/0x60..0x80`, `0x1802` |
| Режим `host` между сессиями | отключить/подключить мышь и проверить `mousecfg mode` | ожидается `host` (переключение режима — единственная консенсусная запись) |

### Ограничения модели

* Аппаратная DPI-кнопка обрабатывается прошивкой мыши, в программируемые
  кнопки она не попадает.
* Режим `On-Board` обратно переключателем проекта не поддерживается: это
  потребовало бы записи профиля в память мыши.

## YJX-CHIP AJAZZ 2.4G (a8a5:2255)

Проверено 2026-11-13, серийник `D1K_251010b271_A72V1`, `bcdDevice 2.71`.
Это мышь на закрытом вендорском протоколе: HID++ у неё нет, поэтому проект
сопровождает её на уровне evdev.

| Что | Значение |
|---|---|
| USB | `a8a5:2255`, 3 интерфейса: 0 — мышь, 1 — клавиатура/consumer, 2 — vendor HID (usage page `0xFF01`, 64 байта in/out) |
| hidraw | `/dev/hidraw4/5/6`; демон их не открывает, вендорский узел (`/dev/hidraw6`) читается только по явной команде |
| evdev | `/dev/input/event20` (`uniq` = серийник), 8 кнопок, два колеса (`REL_WHEEL` и `REL_HWHEEL`) |
| Протокол | вендорский (диалект `mkespn`); HID++ отсутствует |
| Профили по приложениям | работают, ключ устройства — `serial:D1K_251010b271_A72V1` |
| Ремап кнопок и макросы | работают через evdev/uinput: достаточно правила `data/70-mousecfg-input.rules`, hidraw-правило не нужно |
| Как выглядит в CLI | `mousecfg list` → `протокол: evdev (без HID++)` и `доступно: кнопки и макросы` |
| Демон | поднимает мышь, пишет в журнал `evdev: DPI, частота и подсветка недоступны`, `mousecfg devices` и `status` показывают её |
| Команды протокола | `set-dpi`, `set-rate`, `lighting`, `mode` отвечают понятной ошибкой и ничего не отправляют |
| Вендорский канал | интерфейс 2 (`usage page 0xFF01`, 64 байта in/out); проект открывает его **только на чтение** — `mousecfg vendor [--probe]` |
| Протокол YJX | разобран сообществом: кадр `55 cmd sub chk len off_lo off_hi page data…`, ответ `aa …`. Команды чтения: `03/00` идентификация, `08/a5` страницы режимов, `0e/a5` DPI/частота/подсветка, `30/a5`, `fa/ae` |
| Почему не пишем | запись конфигурации сразу уходит в onboard-флеш, а `0d/00` с непустым телом стирает участок памяти. Политика `vendor/guard.py` отклоняет все write-кадры до отправки |

### Что реально удалось прочитать (2026-11-13)

Живой прогон `mousecfg vendor --probe` на этой мыши. Ответы — только чтение:

| Что | Как выглядит | Значение |
|---|---|---|
| Идентификация `03/00` | `YJX.co.mouse` `271220` `Nov 12 2025 18:49:27` `Feb 20 2024 20:18:19` | модель `YJX.co.mouse`, код `271220`, две даты сборки прошивки |
| Конфигурация `0e/a5` | `00 00 04 06 05 90 01 20 03 b0 04 40 06 60 09 80 0c …` | 6 уровней DPI: **400 / 800 / 1200 / 1600 / 2400 / 3200**, активный **2400**, частота опроса **1000 Гц** (код `04`), подсветка выключена (`00`) |
| Серийник `fa/ae` | восемь нулей | у этой модели не заполнен |
| Заряд `30/a5` | 10 байт, первый меняется (`4b`…`52`) | первый байт — **проценты заряда** (0..100); синхронен с байтом 46 ответа `0e/a5`. Ту же команду `0x30` SDK того же контроллера называет «заряд + USB» |
| Заводские коды `08/a5` | страницы 5..6: `20250903170105-3299-3311` | читаемая строка; первые 14 цифр — дата/время `2025-09-03 17:01:05`, дальше две группы кодов. Смысл групп не подтверждён |

Замечание про заряд: байт шумит на ±2% между соседними опросами, поэтому демон
хранит последние 5 значений и показывает медиану — иначе значок в трее дёргался
бы на границах порогов. Для тех же моделей SDK прямо называет команду `0x30`
«заряд и USB», а диапазон 0..100 — единственная осмысленная трактовка.

Заряд показывается в трее: в меню строкой «заряд: N%» и в подсказке при
наведении на значок. Подсказку панель берёт из свойства `Title` элемента
StatusNotifierItem (в noctalia — `formatTrayItemTooltip`), поэтому демон
обновляет `Title` вместе с зарядом.

Поле `current_level` в ответе `0e/a5` (байт 4) — это активный уровень DPI;
в `mousecfg get` он показывается как `dpi`, а `dpi_levels` — как список.
Хвост конфигурации (`01 0a 0a ff …` — LOD, датчик, режим сна) пока не
расшифрован и остаётся в сыром дампе. **Изменить DPI/частоту из Linux нельзя**:
все команды записи запрещены политикой проекта.

### Ограничения

* DPI, частота опроса и подсветка **читаются**, но не настраиваются: протокол
  закрытый, а в onboard-память проект не пишет по определению. Эти параметры
  задаются только штатным ПО мыши или кнопками на корпусе.
* Интерфейс 2 (`usage page 0xFF01`) открывается только для чтения (`mousecfg vendor`).
  Для этого нужен доступ к `/dev/hidraw*` этой мыши: правило `data/60-mousecfg.rules`
  и `sudo udevadm trigger --subsystem-match=hidraw`. Без правила доступен только evdev.
* Автопереход `On-Board → Host`, фичи HID++ и подсветка `RGB_EFFECTS` к таким
  мышам не применяются — в `mousecfg judge` они по-прежнему только для HID++.
* Профиль для этой мыши (пример): `default` с боковыми кнопками
  `side1=browser-back`, `side2=browser-forward` и `browser` для firefox/vivaldi
  (`side1=prev-tab`, `side2=next-tab`). Кнопки применяет evdev-слой.
