# Матрица устройств

Здесь фиксируется только то, что реально проверено на железе. Каждая строка —
результат прогона `mousecfg` и, где это возможно, анализ трафика.

## Logitech G102 LIGHTSYNC (046d:c092)

Проверено 2026-11-11, прошивка `U1 52.00.B0010`, HID++ 4.2, серийник `205C35585247`.

| Что | Значение |
|---|---|
| HID++ узел | `/dev/hidraw2` (interface 1), второй узел `/dev/hidraw1` — обычная мышь |
| Режим до правки | `On-Board` (настройки с хоста игнорировались) |
| Режим после `mousecfg mode host` | `Host`, сохраняется между переоткрытиями устройства |
| DPI | чтение/запись работают, `ADJUSTABLE_DPI 0x2201` |
| Report rate | поддерживаются 1/2/4/8 мс, чтение/запись работают |
| Onboard-профили | есть, **1 слот**; `ONBOARD_PROFILES 0x8100` |
| Divert кнопок | **нет** (`REPROG_CONTROLS_V4 0x1B04` отсутствует) → ремап только через evdev/uinput |
| LED | `RGB_EFFECTS 0x8071`: 1 зона (logo), effects Ids `0x00 disabled, 0x01 static, 0x03 cycle, 0x04 wave, 0x0a breathe, 0x0d, 0x0e decomposition`; `PER_KEY_LIGHTING_V2 0x8081` (3 светодиода) |
| Скрытые фичи | `0x1801, 0x18a1, 0x18b1, 0x1e22, 0x1eb0` — не используются |

### Подсветка (`RGB_EFFECTS 0x8071`)

Протокол проверен на живом устройстве:

* `getInfo` (fn `0x00`, params `FF FF 00`) → 1 зона, capabilities `0x0004`;
  бит `0x0001` (readable) снят, то есть текущий эффект прочитать нельзя.
* Информация о зоне — та же функция `0x00` с `(zone, FF, 00)`; смещение
  `[2:5]` = `location` u16 BE + число эффектов; у G102 `location = 2` (logo),
  7 эффектов.
* Описание эффекта — fn `0x00` с `(zone, slot, 00)`.
* **Волатильная запись эффекта — fn `0x10`**: `zone + slot + 10 байт
  параметров + 0x01`. Именно её использует проект; она не пишет в
  энергонезависимую память.
* **Перед каждой записью эффекта нужен `setSwControl` — fn `0x50`** с
  `01 03 04` (subfn=set, mode=3 «полный SW-контроль», flags=`0x04`).
  Без него прошивка продолжает рисовать цвет onboard-профиля и `setZoneEffect`
  визуально ничего не делает. Команда волатильная (RAM до отключения мыши).
  Является ответом на «подсветка не работает»; тот же приём у Solaar
  (`rgb_power.SW_ACTIVE`). Персистентная `ONBOARD_PROFILES 0x10 [02]` для
  открытия управления не требуется — проверено.
* **Персистентная запись NvConfig — fn `0x30`** (другая функция), запрещена
  политикой (`guard`).
* Проверено: `static red/green/blue` переключаются верно подряд через штатный
  путь (демон + CLI); `breathe` включается и держится до переподключения;
  недоступный эффект и неизвестный параметр отклоняются с ошибкой.

### Что даёт «не писать во флеш»

* Все настройки, которые применяет проект, — волатильные команды HID++ 2.0;
  после отключения мыши они сбрасываются, и это ожидаемое поведение.
* Единственная персистентная операция — однократный переход
  `On-Board → Host` (`0x8100/0x10`). Он выполняется только с
  `--allow-onboard-switch` и попадает в журнал как `persistent-consented`.
* Запрещены и никогда не уходят: `0x8100/0x30`, `0x8100/0x60..0x80`
  (запись onboard-профилей), `0x1802` (reset), `0x1806/0x20`, `0x1e00`,
  `0x00c2/0x20` (прошивка), `0x8071/0x30` (NvConfig подсветки).
  Проверяется тестами в `tests/test_guard.py`.

### Что проверено на живом устройстве

| Проверка | Как | Результат |
|---|---|---|
| Отказ политики | `device.request(0x8100, 0x60)`, `0x1802/0x00`, `0x1e00/0x00` | `DeniedCommand`, в устройство ничего не уходит |
| Ноль персистентных кадров | `python3 scripts/capture-hid.py -- python3 -m mousecfg set-dpi 2400` | «Персистентных операций: 0» |
| DPI волатильно | `set-dpi` → перечитать → `set-dpi` | значение меняется в пределах сессии (800↔1600↔3200) |
| Rate волатильно | `set-rate` 1/2/4/8 мс | значение принимается и читается обратно |
| Демон | `mousecfg daemon -v` + `mousecfg status` | находит мышь, применяет `default`, видит активное приложение |
| Профиль по приложению | профиль `browser` с `match_apps = ["Vivaldi-flatpak"]` | при активном Vivaldi DPI стал 3200, затем вернулся к 1600 |
| GUI | `mousecfg-gui` при запущенном демоне | окно строится, кнопка «Применить» переключает профиль (800↔1600) || Права на evdev-узел | `data/70-mousecfg-input.rules` + `udevadm trigger` | `/dev/input/event3` доступен: `mousecfg inputs` показывает мышь и её кнопки |
| Ремап кнопок | `mousecfg run-profile examples/g102-buttons.toml --seconds …` | `EVIOCGRAB` встаёт, события ретранслируются, `--seconds` корректно выключает перехват |
| Подсветка волатильно | `mousecfg lighting --effect static --color '#ff0000' --brightness 50`, затем `breathe` | эффект включается, `static` притемняет цвет (0x800000), `breathe` шлёт `intensity`; держится до переподключения; `fn 0x30` отклоняется как `DeniedCommand` |
| Подсветка берёт SW-контроль | `mousecfg lighting --effect static --color '#00ff00'` на мыши в host | перед `setZoneEffect` уходит `setSwControl 01 03 04`; красный/зелёный/синий переключаются верно подряд (без claim цвет «залипал» на onboard-профиле) |
| Трей и хоткей | `mousecfg-tray` + панель StatusNotifierWatcher | иконка `mousecfg` регистрируется; на niri трей портал не трогает и не плодит зависших окон |
| Хоткей через niri | `mousecfg keybinds --install` + `niri msg action load-config-file`, затем `Alt+Shift+Right` | активный профиль переключается на следующий (`default`→`shooter`) |
| Запись макроса в GUI | в диалоге профиля выбрать кнопку `side1`, «Записать макрос», нажать `Ctrl+Shift+T` | шаг `ctrl+shift+T` появляется списком, макрос сохраняется с id `профиль-side1` и подставляется в назначения кнопки |
| Сквозная проверка evdev | виртуальный источник → `Remapper` → виртуальный приёмник | движение насквозь; `side1`→`ALT+LEFT`, `middle`→`CTRL+C`, `side2`→макрос; непривязанная `BTN_RIGHT` проходит как есть; p95 ≈ 0.4 мс |
| Виртуальное устройство | `data/71-mousecfg-virtual.rules` | `/dev/input/eventN` устройства `mousecfg virtual input` получает ACL пользователя сессии |

### Что нужно проверить вручную

| Проверка | Как | Ожидание |
|---|---|---|
| Волатильность через переподключение | `python3 scripts/replug-test.py` (задать значения, затем физически переподключить мышь) | после переподключения значения возвращаются к дефолту |
| Независимый дамп USB | `sudo python3 scripts/capture-hid.py --usbmon capture.pcap -- python3 -m mousecfg set-dpi 1600` | в трафике нет `0x8100/0x60..0x80`, `0x1802` |
| Режим `host` между сессиями | отключить/подключить мышь и проверить `mousecfg mode` | ожидается `host` (переключение режима — единственная консенсусная запись) |

### Ограничения модели

* Аппаратная DPI-кнопка обрабатывается прошивкой мыши, в программируемые
  кнопки она не попадает.
* Режим `On-Board` обратно переключателем проекта не поддерживается: это
  потребовало бы записи профиля в память мыши.
